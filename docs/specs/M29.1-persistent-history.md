# M29.1 — persistent cross-session history — SPEC

**Status: approved (overnight batch). → 2.9.1.** Conversations survive
restarts as plain local files, consistent with the file-backed design.

## Storage & privacy model

- **`profiles/<name>/history/<conversation_id>.jsonl`** — one JSON object per
  line: `{ts, role, content, ...meta}` (assistant turns carry
  provider/model/success). Plain, greppable, append-only.
- Conversation ids are `^[A-Za-z0-9_-]+$` (UTC stamp + short suffix) and are
  **validated before any path is built** (write-safety style traversal guard).
- **Chat content stays private:** `profiles/*/history/` is **gitignored**
  (chat text must never land in the repo) and **portable bundles never
  include it** (the M28 allowlist exports only the sanitized profile +
  `memory/` — unchanged, now stated in docs). Full **backups DO include it**
  (backup = same-host restore of everything; documented).

## Scope

1. **`history/manager.py`** (new top-level package — added to the pyproject
   packages list per the M26.4 invariant): `ConversationStore(profile_dir)`
   with a per-store lock (memory-manager pattern; `/chat` appends from worker
   threads): `new_conversation()`, `append_turn(id, role, content, meta)`,
   `list_conversations()` (id, started_at, turn count, first-user-message
   preview; newest first), `read(id)`, `delete(id)`.
2. **`core/chat_turn.py` seam:** `record_turn(store, conv_id, role, content,
   meta)` — swallows every error; a history write must never fail an answered
   turn (same contract as `extract_memory`).
3. **`/chat` integration:** `ChatRequest.conversation_id` (optional,
   regex-validated 400) — absent → a new conversation is created; the user
   turn is recorded before routing, the assistant turn after (with
   provider/model/success); `ChatResponse.conversation_id` returns it. Store
   lives as `main._history` (lifespan init; **re-pointed by
   `POST /profiles/activate`** like memory/saved).
4. **Endpoints** (`app/routers/history.py`): `GET /history/conversations`,
   `GET /history/conversations/{id}`, `DELETE /history/conversations/{id}`.
5. **UI:** `sendMessage` threads the `conversation_id` (captured from the
   first response, sent on subsequent posts; `clearConversation` resets it →
   next send starts a fresh conversation). History panel's Conversation tab
   gains a **Past conversations** list (from the store) with load-on-click
   (renders turns into the chat, resumes that conversation id).
6. **CLI:** deliberately not in this milestone — the REPL (M29.2) is the CLI
   surface that joins persistent history.
