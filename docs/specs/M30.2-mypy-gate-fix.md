# M30.2 — Green mypy gate + CalDAV ETag fix — SPEC (→ 3.0.1)

**Status: approved (user, 2026-07-16), implemented. Bumps to 3.0.1: the ETag
repair is a runtime behavior fix, not just typing.**

## The finding (from a live incident)

A claude-CLI session run from inside the repo (see M30.1's incident) reported
"type-check issues" via the SessionStart hook. Verified: `mypy .` exits 1 on a
fresh 3.0.0 checkout — 8 errors, reproduced on two machines with identical
pins (Python 3.11, mypy 2.3.0, caldav 3.2.1). So `task ci`'s typecheck step is
red.

**Root cause:** caldav 3.x ships `py.typed` AND a PEP 562 lazy loader typed
`def __getattr__(name: str) -> object` in its `__init__.py`. Every module-attr
access (`caldav.DAVClient`, `caldav.Calendar`, …) therefore types as `object`
→ `"object" not callable`.

**The one that mattered:** `caldav_lib.dav.GetEtag()`
(caldav_integration/client.py:229) is not just a typing complaint —
**`caldav.dav` does not exist in caldav 3.x**, so the ETag fetch has raised
AttributeError into its `except: etag = ""` guard on every call since the
caldav 3 pin (M26.12 era). mypy's `attr-defined` error was pointing at a real,
silently-swallowed runtime bug: `dav_status` etags have always recorded as
`""`.

**Why the gate looked green before:** it never was verified by exit code.
Recent milestone logs (and the REVIEW-3.0 gate lines) assessed mypy through a
shell pipe (`mypy . | tail`), which reports the pipe's exit status, not
mypy's. Erratum recorded in REVIEW-3.0.

## Scope

1. **Fix the real bug:** the ETag block imports `GetEtag` from its true home,
   `caldav.elements.dav` (verified importable and correct on the pinned
   3.2.1). ETags now actually populate on real servers; in the mocked suite
   the surrounding try/except keeps behavior identical (fake caldav modules
   have no `elements` submodule → import fails → `etag = ""` exactly as
   before).
2. **Suppress the 7 lazy-attr false positives precisely:** per-line
   `# type: ignore[operator]` with a comment naming the cause (caldav's
   `__getattr__ -> object`). NOT the from-real-submodule alternative: the DAV
   test architecture mocks at the `caldav` module boundary
   (`sys.modules["caldav"]`, `patch("caldav.Calendar")`), and real-submodule
   imports would silently bypass every fake — a wide, hermeticity-risking
   test rewiring for zero runtime benefit.
3. **Make the gate un-maskable in prose:** INVARIANTS' type-gate section
   gains: the gate is `mypy .`'s EXIT CODE (never assess it through a pipe),
   plus the caldav `__getattr__ -> object` note so a future agent doesn't
   "clean up" the ignores.
4. **Test:** a regression test asserting the GetEtag import path exists on
   the pinned caldav (`from caldav.elements.dav import GetEtag`) so a future
   caldav bump that moves it fails loudly instead of silently re-breaking
   etags.

## Out of scope

- Retyping the DAV layer against caldav's real submodules (would require
  re-architecting the test fakes; DEFER — trigger: if the ignores exceed ~a
  dozen or caldav's typing stabilizes its lazy loader).
- The cwd context-bleed fix (M30.3, separate).

## Self-review / risks

- The ignores are `[operator]`-coded, not bare — they suppress exactly the
  lazy-loader artifact and nothing else on those lines.
- ETag change is behavior-visible only in `dav_status` metadata (etags dict);
  no API shape changes. CalDAV stays disabled by default; nothing runs
  without explicit enablement.
- Version: **3.0.1** (runtime fix). Docs: CHANGELOG, INVARIANTS, REVIEW-3.0
  erratum, specs README, CLAUDE.md roadmap line.
