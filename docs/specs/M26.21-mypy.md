# M26.21 — mypy type-checking (lenient adoption) — SPEC

**Status: specced, awaiting go-ahead. Best after M26.19/M26.20. Do NOT implement
without explicit approval.**

## Why

The code is already well-annotated, so a lenient mypy pass is cheap to adopt and
catches contract/shape drift a test can miss — a handler returning the wrong
shape, or a `None` slipping where a client is expected. It's the type-level
complement to ruff's name-level checks.

## Scope probe (measured, lenient `--ignore-missing-imports` on core/+providers/)

**5 errors, 2 files** — representative, not exhaustive:
- `providers/router.py:243/263/285/296` — `Item "None" of "RequestTrace | None"
  has no attribute "add"` (×4). Likely a real narrowing gap: the trace is
  created then used under a truthiness/config guard mypy can't follow. Fix by
  narrowing (assign to a local after the `if`, or assert non-None) — a genuine
  robustness improvement, not just appeasement.
- `core/loader.py:14` — missing `types-PyYAML` stub. Fix by adding
  `types-PyYAML` to dev deps.

A full-tree run will surface more (esp. in `main.py`, the routers, and the DAV
clients); the milestone's first job is to **measure the full count** and decide
config strictness from the real number.

## Scope

1. **Dev deps:** add `mypy==<installed>` and `types-PyYAML`,
   `types-requests` (and any other `types-*` mypy flags as missing).
2. **`[tool.mypy]` in `pyproject.toml`** — start deliberately lenient so adoption
   is a bounded diff, then tighten later:
   - `python_version = "3.10"`, `ignore_missing_imports = true`
     (caldav/vobject/openai ship no stubs), `warn_unused_ignores = true`.
   - **Do NOT enable** `strict`, `disallow_untyped_defs`, or
     `disallow_any_generics` initially.
   - `exclude = ['\.venv', 'tests/']` for the first pass (test files use heavy
     MagicMock/monkeypatch dynamism; type-checking them is high-noise,
     low-value — add later if wanted).
   - Optionally scope the first adoption to the app packages via explicit
     `files = [...]` if the full-tree count is large; expand in follow-ups.
3. **Fix the errors the chosen scope surfaces.** Prefer real fixes (narrowing,
   `assert`, precise return types) over `# type: ignore`; where an ignore is
   unavoidable, make it specific (`# type: ignore[union-attr]`) and comment why.
   Re-run the full pytest suite after — type fixes should be behaviour-neutral;
   verify.
4. **Taskfile:** `typecheck` task (`mypy .` or the scoped path). Add to the
   `SessionStart` hook as a reporting step (like lint), and to CI (M26.20) once
   green.
5. **Version:** bump **only if** a fix changes runtime behaviour (e.g. the
   router narrowing alters a code path); a pure-annotation pass is docs-like. Use
   judgement at implementation; default to a patch bump if any `.py` logic
   changed. CHANGELOG + INVARIANTS note.

## Self-review notes
- Decide scope (whole-tree vs app-packages-first) from the measured full count —
  don't commit to "strict everywhere" in one milestone; that's how type adoption
  stalls.
- The `RequestTrace | None` fix touches hot routing code — keep the change
  minimal and covered by the existing `test_diagnostics.py` / `test_provider_*`
  tests; add a targeted test if the narrowing changes a branch.

## Out of scope
- Strict mode / 100% annotation coverage — future, incremental.
- Type-checking the test suite.
