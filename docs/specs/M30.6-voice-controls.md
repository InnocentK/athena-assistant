# M30.6 — Voice output/input controls — SPEC (→ 3.0.5)

**Status: approved (user, 2026-07-17 triage), implemented.**

## Findings (live desktop testing, all confirmed in code)

1. Every successful answer is read aloud — `voice.speak()` fires
   unconditionally (M5 design), with no way to turn it off.
2. The default synthesis voice is whatever the browser picked; no picker.
   (TTS is browser `SpeechSynthesis` — completely independent of the AI
   providers; `getVoices()` exposes the system's voices.)
3. The mic stops on the first pause (`continuous = false`).
4. The transcript auto-sends instead of landing in the input for review.

## Changes

**Preferences live in the BROWSER (`localStorage`), not the profile.** These
are per-device accessibility/interaction settings (phone ≠ desktop needs);
profile.yaml's narrow editable set stays untouched (INVARIANTS). Key
`athena-voice-prefs`, JSON, guarded reads/writes (private-mode localStorage
can throw → in-memory fallback). Defaults, per the user's direction:

| pref        | default | meaning                                            |
|-------------|---------|----------------------------------------------------|
| `speak`     | false   | read answers aloud (was: always on)                |
| `voiceName` | ""      | SpeechSynthesis voice by name ("" = browser default)|
| `autoSend`  | false   | send transcript immediately (was: always on); off → transcript lands in the input for review |
| `continuous`| false   | keep listening until the mic is clicked again (off = M5 stop-on-pause) |

- `voice.js`: `speak(text, voiceName)` selects a matching voice from
  `getVoices()` (graceful fallback to default); `listVoices()` helper;
  `continuous` property — in continuous mode final results accumulate in a
  buffer and `onTranscript` fires once on end (stop click), preserving
  single-utterance behavior otherwise.
- `chat.js`: TTS call sites (streaming + buffered) gate on `prefs.speak`;
  `onTranscript` honors `autoSend` (off → value into the input, focus,
  resize); PTT click applies `prefs.continuous`; Settings → Profile tab
  gains a **Voice** section — instant-apply controls (change → localStorage
  immediately, labeled "Saved in this browser") deliberately separate from
  the server-persisted "Save settings" button. Voice dropdown repopulates on
  `voiceschanged` (voices load async in some browsers).

## Tests

- jsdom (`tests/js/voicePrefs.test.js`): fake `speechSynthesis` +
  `SpeechSynthesisUtterance` + `webkitSpeechRecognition` injected before
  boot. Default = silent (speak NOT called on a successful answer);
  `speak:true` pref → called; transcript with default prefs → input
  populated, NO send; `autoSend:true` → sent. localStorage is real in jsdom.
- Python source-structure: prefs key + Voice-section strings present in
  chat.js; voice.js handles `continuous`.

**3.0.5.** CHANGELOG, TESTING, specs README, CLAUDE.md queue tick.

## Self-review / risks

- `getVoices()` returning `[]` until `voiceschanged` — handled by
  re-population; picker shows "(browser default)" meanwhile.
- Continuous mode's accumulated buffer resets per session; errors mid-
  session still deliver whatever accumulated (better than losing it).
- The existing pre-M30.6 behavior (always speak, always auto-send) remains
  reachable by flipping the toggles — nothing is removed.
