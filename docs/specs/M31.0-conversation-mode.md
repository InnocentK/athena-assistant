## What it is

The cheap probe of the whole voice direction (per the M31 roadmap decision):
make talking to Athena feel *live* using only what already exists — the M5
Web Speech plumbing, M30 streaming, and the M30.6 voice-prefs scaffolding.
Live with it for a week; whether it earns M31.1+ (Athena Live, the
self-hosted pipeline) is decided by use, not speculation.

## Three capabilities

### 1. Streaming speech — speak sentences as they arrive
Today TTS (when enabled) waits for the `done` event and reads the whole
reply. With conversation mode ON, the streaming path speaks each *completed
sentence* as chunks assemble it:

- Sentence boundary: a naive splitter (`. ! ?` followed by whitespace/EOL,
  with a min-length guard so "e.g." doesn't fire; deliberately dumb — this
  is a probe, not NLP). Remaining tail is spoken at `done`.
- `voice.js` gains `enqueue(text, voiceName)` — like `speak()` but WITHOUT
  the leading `cancel()`, so utterances queue naturally in the synthesis
  engine. `speak()` (cancel-then-say) remains for the Test button and
  whole-reply mode.
- The `done` event does NOT re-speak reconciled text (the authoritative-text
  reconcile stays visual-only). Buffered-fallback turns speak whole, as
  today.

### 2. Hands-free loop — auto-listen after Athena finishes speaking
When conversation mode is ON and the reply's last utterance ends, the mic
re-opens automatically (using the existing continuous/single-utterance pref).
The loop stops when: the user clicks the mic off, sends a typed message, an
STT error fires, or the tab loses visibility. The mic button gets an active
"conversation" visual state so it's always obvious the loop is live.

### 3. Barge-in — interrupt Athena by talking (or acting)
Speech synthesis is cancelled the moment the mic re-opens AND on any
transcript delivery, plus on Send/typing-enter. Interrupting mid-reply never
loses text — the full reply is still rendered (speech is a *view* of the
answer, never the answer).

## Settings

One new toggle in the M30.6 Voice section: **"Conversation mode"** (default
OFF), localStorage like its siblings. Turning it ON implies speak-responses
for the session's spoken loop (visually indicated); it does NOT rewrite the
user's stored `speak` pref.

## Honest limits (stated in docs, unchanged from the roadmap entry)

Web Speech STT is Chromium/Safari (not Firefox); CLI-transport providers
answer whole, so their "streaming speech" is one utterance after the wait —
the live feel needs an API-transport provider; the mic requires a secure
context (HTTPS over Tailscale — REMOTE-ACCESS.md, verified live during the
mobile pass); markdown/code blocks are spoken as-is (M5 parity — a
"speakable text" filter is a candidate M31.x refinement, not in the probe).

## Self-review / risks

- SpeechSynthesis queue behavior varies slightly across engines (macOS vs
  Chrome-on-Windows voices); the design only relies on FIFO queue + cancel,
  the two universally supported operations.
- Auto-listen must NEVER start without a prior user gesture in the session
  (browser autoplay/mic policies): the loop only arms after a mic click, so
  the gesture requirement is satisfied by construction.
- Infinite loop risk (Athena hears herself): mitigated by cancelling
  synthesis before the mic opens (barge-in ordering) — the mic never opens
  while Athena is speaking. Echo via speakers remains physically possible
  (headphones recommended for the probe; echo cancellation is an M31.x
  question), stated in docs.
- Rollback is trivial: the toggle defaults OFF and every change is gated on
  it; OFF-path behavior is pinned by the existing M30.6 tests.

## Self-review amendments (pre-implementation, per pre-approval)

- **A1 — conversation mode implies auto-send for voice transcripts.** A
  hands-free loop where every utterance waits for a manual Send isn't
  hands-free; the toggle implies it exactly as it implies speaking. The
  stored `autoSend` pref is not rewritten (same principle as `speak`).
- **A2 — the M30.6 call-site count pin evolves, knowingly.** Whole-reply TTS
  gates refactor to a shared `_shouldSpeak(vp)` (`speak || conversation`);
  the source-structure pin now counts `_shouldSpeak(` (definition + two call
  sites) and separately asserts the streaming-enqueue path is gated on
  `conversation`. The REVIEW-3.0.z blessing (B5) anticipated exactly this:
  extend the pin consciously, never delete it.
- **A3 — zero-utterance turns re-arm the mic immediately.** Failed replies
  (error bubble, nothing spoken) re-open listening right away — Athena
  "finished speaking" vacuously, and conversational retry ("try again") is
  the natural recovery.
- **A4 — `speak()` now returns its utterance** (was: undefined) so buffered
  turns can arm the loop on speech end; behavior otherwise identical.
