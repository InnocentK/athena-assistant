# M26.24 — Coverage measurement — SPEC

**Status: specced, awaiting go-ahead. Do NOT implement without explicit approval.**

## Why

There's no coverage signal. The M26.18 conflict-endpoint bug is the cautionary
tale: 438 tests passed while a whole endpoint was broken (the lines *were*
executed, so coverage wouldn't have caught that specific case) — but coverage
*does* surface genuinely unreached branches/error paths and gives a number to
hold the line on so coverage can't silently erode.

## Measured baseline (this session)

`pytest --cov=.` reports **~86% TOTAL** — but that run *included the test files
themselves* in the denominator (they're ~100%, inflating the number). The
milestone must measure **source-only** (exclude `tests/`) for an honest figure,
then set a floor slightly below it.

## Scope

1. **Dev dep:** `pytest-cov==<pinned>` in `requirements.txt`.
2. **Config** (`[tool.coverage.run]` / `[tool.coverage.report]` in
   `pyproject.toml`):
   - `source = ["."]`, `omit = ["tests/*", ".venv/*", "*/__pycache__/*"]` so the
     percentage reflects *application* code only.
   - `[tool.coverage.report]`: `show_missing = true`, and a `fail_under = N`
     where **N = (measured source-only %) rounded down to a safe floor** (decide
     N from the real source-only number at implementation — likely ~80, NOT 86;
     set a floor that's green today with a little headroom, not a ceiling).
   - `exclude_lines`: the usual pragmas (`pragma: no cover`,
     `if __name__ == .__main__.:`, `raise NotImplementedError`).
3. **Taskfile:** `coverage` task (`pytest --cov --cov-report=term-missing`) and
   `coverage:html` (`--cov-report=html`, opens `htmlcov/`). `.gitignore` already
   lists `.coverage`/`htmlcov/`; confirm.
4. **CI (M26.20):** add `--cov --cov-fail-under=N` to the pytest step (or a
   dedicated coverage step) so coverage regressions fail CI. Keep it in the
   existing `test` job — no new job.
5. **Do NOT chase 100%.** Use the term-missing report to find and cover a few
   genuinely-worth-it gaps (an untested error branch, a whole unexercised
   helper) — cap the milestone at a *small* set of high-value additions, don't
   turn it into a coverage-grind. Anything intentionally uncovered gets a
   `# pragma: no cover` with a reason.
6. **No app code change (unless a test-gap fix reveals a real bug) → likely no
   version bump.** CHANGELOG + INVARIANTS note ("coverage floor N% — `task
   coverage`; CI fails below it").

## Self-review notes
- The floor is a *ratchet-down guard*, not a target — set it below today's real
  number so honest refactors don't trip it, then raise it deliberately later.
- Branch coverage (`--cov-branch`) is more meaningful than line coverage but
  noisier; decide at implementation whether to enable it now or defer.
- Coverage measures execution, not correctness (M26.18 proves it) — it
  complements the suite, never replaces good assertions.

## Out of scope
- Mutation testing; per-file coverage gates; coverage of the JS suite.
