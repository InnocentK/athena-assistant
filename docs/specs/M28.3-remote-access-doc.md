# M28.3 — remote-access doc — SPEC

**Status: approved (overnight batch). DOCS ONLY — no code, no version bump.**

## Why
`docs/PLATFORMS.md` (M26.27) states the posture (no auth layer; perimeter's
job) and names the two safe patterns in two paragraphs. This milestone writes
the fuller **how-to** those paragraphs point at — the last item from the
remote-access design discussion, kept docs-only by decision.

## Scope
1. **New doc `docs/REMOTE-ACCESS.md`:**
   - The rule, restated once: Athena has no authentication and must never bind
     an untrusted interface; remote reach is the operator's responsibility,
     like any self-hosted server app.
   - **Pattern A — Tailscale/VPN (recommended):** keep the bind private, join
     machines to a tailnet, reach `http://<tailnet-name>:8000` from any device
     on it; note `tailscale serve` for HTTPS (which also unlocks PWA install,
     M26.28); phones use the same pattern + the PWA.
   - **Pattern B — authenticated reverse proxy + TLS:** Athena stays on
     loopback; Caddy/nginx terminates TLS and enforces auth (basic-auth/OIDC);
     one illustrative Caddy snippet. Explicit anti-pattern list: never
     `0.0.0.0` on a public bridge, never port-forward Athena directly, no auth
     shim inside Athena.
   - Verification: how to check what's bound (`ss/lsof`), and that the UI/CLI
     work over the chosen path.
2. **Wire-up:** link from `docs/README.md` (operating section) and swap
   `PLATFORMS.md`'s remote-access section to point at the new doc for detail
   (keep its summary — it's the matrix's canonical caveat, don't duplicate
   beyond that).
3. **No bump.** CHANGELOG entry; hygiene clean; links resolve.
