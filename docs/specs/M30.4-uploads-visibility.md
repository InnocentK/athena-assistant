# M30.4 — Uploads visibility + attach UX — SPEC (→ 3.0.3)

**Status: approved (user, 2026-07-17 desktop-testing triage), implemented.**

## Findings (from live desktop testing)

Uploads WORK — files verified on disk with correct timestamps — but three UI
defects made them look broken:

1. **The raw `<input type="file">` renders next to the 📎 button.** It has
   `class="hidden"`, but chat.css defines only *scoped* `.hidden` rules
   (`.memory-panel.hidden`, …) — there has never been a bare one, so the
   browser default applied. Visible since M29.3 shipped.
2. **The Files tab never shows uploaded files.** The M20-era listing globs
   `*` non-recursively per allowlist root — `data/uploads/<file>` is one
   level too deep. The listing predates uploads existing.
3. **Directories appear as clickable "files".** `search_files()` appends
   every glob match without an `is_file()` filter, so `data/uploads` itself
   listed as an entry whose preview correctly 400s ("Cannot preview").

## Changes

- `files/manager.py::search_files` — skip non-files (`is_file()` guard):
  a "files" listing/count returns files, everywhere (API + panel). Root fix
  for defect 3.
- `static/css/chat.css` — `#attach-input { display: none; }` (scoped to the
  element, NOT a global `.hidden` rule — the scoped `.hidden` users hide via
  their own rules and a global `display:none` could interact with them).
- `static/js/chat.js::loadHistoryFiles` — fetch `*` AND `uploads/*`
  (parallel), merge + dedupe; count reflects the merged list; token guard
  unchanged. Uploads become visible without turning the panel into a full
  recursive tree (deliberate: `**/*` would surface every nested artifact).
