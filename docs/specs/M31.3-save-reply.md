# M31.3 — Save reply as file — SPEC (→ 3.1.3)

**Status: approved (user, 2026-07-19: "Yes, implement M31.3 now") — probe
finding #2, from using voice mode as an actual assistant.**

## Problem / decision record

The user asked chatgpt (via Athena) for notes on Jupiter "as a markdown
file" and got copy-paste instructions — correctly, because **every provider
is a pure text-in/text-out LLM by policy** (API transports have no
filesystem; the claude CLI's tools are deliberately denylisted, M30.7).
Conversation export (M29.4) gets the whole conversation out, but not "this
one reply as a file."

Decision: a per-reply **Save button** — the USER initiates, Athena's own
deterministic code writes. The pure-LLM boundary is untouched: the model
never gains an action. Voice-commanded saving ("Athena, save that") is
model-initiated intent parsing — that stays in the Later tool-calling
safety framing, not here.

## Change (frontend-only)

- Each **assistant** reply's meta line (buffered, streaming, and
  history-restored renders; never welcome, never error bubbles) gains a
  small **"Save"** button.
- Click → the reply text is POSTed to the **existing `POST /files/upload`**
  endpoint as a multipart file named `reply-YYYYMMDD-HHMMSS.md`
  (`text/markdown` blob). **No new endpoint, no new write path**: the
  upload envelope applies unchanged — basename sanitization, exclusive
  create with unique-suffix on collision, 10 MB cap, `data/uploads/` only.
  The file then appears in the Files tab (M30.4 `uploads/*`) and can be
  re-attached to later messages like any upload.
- Feedback is inline and quiet: the button becomes "Saved ✓" (title = the
  returned path) and disables; on failure it shows "Save failed" and
  re-enables. No bubbles, no layout shift.
- Filename is deliberately dumb (timestamp, not content-derived) —
  predictable, collision-friendly, rename-on-disk if you care. CLI surface
  is deliberately out of scope (shell redirection + `athena history
  export` already cover it).

## Tests

- jsdom (`tests/js/saveReply.test.js`): streamed and buffered replies get
  the button; click POSTs multipart to `/files/upload` with an `.md`
  filename and the reply text as content; success flips to "Saved ✓" and
  disables; failure re-enables; the welcome message has no Save button.
- Pins (`test_ui_correctness.py`): `_replySaveButton(` = definition + the
  two render call sites (appendMessage + `_finishStreamingBubble`); the
  save posts to `"/files/upload"` (no new endpoint string).

## Self-review / risks

- A LAN peer could always hit `/files/upload` directly (single-user,
  no-auth model, SECURITY.md) — this feature adds zero new surface.
- Error-bubble text is never saveable (failure text is not content — same
  spirit as M26.10's never-replay rule).
- The saved text is the AUTHORITATIVE rendered reply (post-reconcile
  bubble text), byte-identical to what history records.
