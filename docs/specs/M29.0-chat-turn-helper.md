# M29.0 — shared chat-turn helper — SPEC

**Status: approved (overnight batch). → 2.9.0. First milestone of the M29
Conversations epic** — the prerequisite refactor: one code path assembling a
chat turn, used by both the web `/chat` handler and the CLI, so M29.1
(persistent history) and M30 (streaming) get built once, not twice.

## What is actually shared (and what deliberately is not)

Shared today, duplicated across `app/routers/core.py::chat` and
`cli/main.py::main`:
1. **Message-list assembly** — history turns + the new user message.
2. **System-prompt extraction** — `profile.get("system_prompt") or None`.
3. **Memory auto-extraction semantics** — best-effort, never fails an
   answered turn.

Deliberately NOT unified: the **execution models**. The HTTP path wraps
routing in `asyncio.wait_for(to_thread(...), _ROUTE_TIMEOUT)` (M26.5
loop-responsiveness) and the CLI drives a spinner + `on_attempt` callback
(M27.0). Those are surface-specific by design and stay where they are.

## Scope

1. **New module `core/chat_turn.py`** (no FastAPI imports — usable by both
   surfaces):
   - `build_turn_messages(history, new_message)` — history as an iterable of
     `(role, content)` pairs → `list[Message]` ending with the new user turn.
   - `system_prompt_from(profile)` — the exact `or None` semantics both
     surfaces use today.
   - `extract_memory(memory_mgr, user_message, response_content)` — the SYNC
     core of auto-extraction: None-manager tolerant, swallows every exception
     (logged), returns bool for tests. The HTTP path keeps its own
     `wait_for`/`to_thread` + timeout wrapper AROUND this; the CLI calls it
     directly (its MemoryManager construction stays local).
   - Module docstring names the seams M29.1/M30 will extend (turn recording,
     streamed assembly).
2. **Rewire both call sites** to the helpers with **byte-identical
   behavior** — same timeouts, same logging, same stdout/stderr contract,
   same non-fatality.
3. **Tests** — `tests/test_chat_turn.py` units (assembly order/roles, empty
   history, `or None` prompt semantics incl. empty string, extract_memory
   swallowing + None-manager). The existing 501-test suite is the regression
   net for the rewiring.
