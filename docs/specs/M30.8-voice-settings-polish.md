# M30.8 — Voice settings polish — SPEC (→ 3.0.7)

**Status: approved (user, 2026-07-17 Pt 2 triage), implemented.**

## Findings

1. **Voice dropdown cut off at the panel edge** (bug, introduced M30.6): the
   `.settings-row` flex children have no shrink constraint, and macOS voice
   names are far longer than any value the rows previously held — the select
   overflows instead of shrinking.
2. **No way to hear a voice before using it** (user feature request): the
   picker saves fine but gives no feedback until the next spoken answer.

## Changes

- `chat.css`: `.settings-row .settings-edit-select { min-width: 0;
  flex: 0 1 auto; max-width: 60%; }` — selects shrink inside the row and the
  browser clips option text within the control (both routing selects benefit
  on narrow/mobile widths too).
- `chat.js` (Voice section): a **"Test voice"** button that speaks
  "Hello. I'm Athena. How can I help?" in the currently selected voice —
  deliberately ignoring the speak-responses toggle (an explicit click IS the
  request to hear it; the toggle governs *answers*).

## Blessed in this milestone's docs (approved, no code)

The ops-files toggle showing `audit/*.py` source is **as designed**: the
`audit/` package intentionally mixes source with the logs it writes (its own
docstring documents this), the allowlist grants it search+read, and the view
sits behind an explicit toggle with an amber notice. Recorded in INVARIANTS
so nobody "fixes" it into a filter later without a reason. The stray
`data/test.yaml`/`m6test.txt` were the user's local Milestone-6-era leftovers
(gitignored dir) — user deletes them; nothing to change in the repo.
