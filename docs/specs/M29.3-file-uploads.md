# M29.3 — real file uploads — SPEC

**Status: approved (overnight batch). → 2.9.3.**

## Design (deliberately narrow)

Uploads land as plain files under **`data/uploads/`** — which the shipped
`config/files.yaml` already allowlists read/write — so everything downstream
(reading a file into a question, file search, saved searches) works through
the **existing, guarded file machinery**. No new read path, no prompt
auto-injection: the user references the uploaded file naturally and the
allowlist governs access, exactly as for any other file.

1. **`POST /files/upload`** (multipart; `python-multipart` is already a
   pinned dep): saves to `data/uploads/<sanitized-name>`.
   - **Filename sanitization**: basename only; characters outside
     `[A-Za-z0-9._-]` replaced with `_`; leading dots stripped (no dotfiles);
     empty → `upload`. Collision → `-1`, `-2`, … suffix (never overwrite).
   - **Size cap 10 MB**, enforced while streaming to disk (chunked copy,
     partial file removed on breach) → 413. Empty file → 400.
   - Content is treated as opaque bytes — never executed, never parsed.
   - Ops-audited (`file_upload`, name + size only).
2. **`GET /files/uploads`** — list (name, size, mtime), newest first.
3. **UI**: a 📎 button beside the input; picking a file uploads it and inserts
   `[Attached file: data/uploads/<name>]` into the message box — the model
   sees the reference; the user stays in control of what is asked about it.
4. Storage note added to BACKUP docs (uploads ride in `data/`-inclusive
   backups only when `include_data=true`, unchanged behavior).

## Tests (`tests/test_uploads.py`)
Round-trip (upload → listed → readable via the existing `/files/read`),
traversal-shaped name sanitized into the uploads dir (`../../evil.txt` →
`evil.txt`, file created only under `data/uploads/`), oversize → 413 with no
file left behind, empty → 400, collision → unique suffixed names.

## Self-review
- The allowlist remains the single access-control point — the upload endpoint
  only ever *writes into* its own directory, with a name it fully controls.
- 10 MB is a config-free constant for now; make it configurable only if it
  ever pinches (YAGNI).
- Out of scope: multi-file upload, drag-and-drop, previews, automatic
  prompt injection of file contents, deletion endpoint (files are visible in
  the allowlisted tree and manageable there).
