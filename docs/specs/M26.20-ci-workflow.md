# M26.20 — CI workflow — SPEC

**Status: specced, awaiting go-ahead. Depends on M26.19 (lint must exist and be
green first). Do NOT implement without explicit approval.**

## Why

The `SessionStart` hook runs lint+suite locally, but nothing *enforces* green on a
push. CI turns "the agent remembered to run tests" into "a red branch can't
merge" — the structural backstop a weak agent most benefits from. It also
verifies the pinned deps actually install from scratch (guards M26.19's pins).

## Preconditions
- M26.19 shipped: `task lint` exists and passes; `requirements.txt` pinned. ✅

## Implementation decision (self-answered 2026-07-14, user away)

**Finding: the project is not under git at all** — no repo in the container copy
or on the Mac, no remote. A bare CI workflow file would therefore be *inert* (it
can't run until the project is a GitHub repo). Rather than ship a dead file, this
milestone delivers value that works **today** and is turn-key for later:

1. **`task ci`** — a Taskfile task that runs the exact CI gate locally
   (lint → editable install → suite). This makes "one reproducible gate" real
   immediately, for the user or a future agent, with no remote needed.
2. **`.github/workflows/ci.yml`** — the GitHub Actions workflow, ready to run the
   moment the project gets a GitHub remote (GitHub is the default; the tooling
   here uses `gh`/GitHub conventions).
3. **`docs/CI.md`** — what CI checks + how to activate it (`git init`, create a
   GitHub repo, push) + the no-secrets rationale.

No app code changes → **no version bump** (stays 2.6.19), mirroring the
docs-only M26.11 precedent. CHANGELOG entry notes CI is inert until a remote
exists.

## Scope (GitHub Actions variant)

1. `.github/workflows/ci.yml`:
   - Triggers: `push` (all branches) + `pull_request`.
   - One job `test`, `runs-on: ubuntu-latest`, matrix `python-version:
     ["3.10", "3.11"]` (3.10 is the floor per pyproject `requires-python`;
     3.11 is what's tested locally — proving both guards against
     version-specific breakage).
   - Steps: checkout → `actions/setup-python` (with pip cache keyed on
     `requirements.txt`) → `pip install -r requirements.txt` →
     `pip install -e .` (proves the console-script/packaging path, incl. the
     `app`/`app.routers` packages added in M26.18) → `ruff check .` →
     `pytest -q`.
   - Fast: the suite is ~30s and fully mocked (no network/credentials needed —
     the M26.17 conftest hermeticity fixture guarantees no real provider CLI
     runs, so CI needs no secrets).
2. **A tiny status note** in `README.md` (a CI badge once the remote exists) and
   in `docs/VALIDATION.md` ("CI runs lint+suite on every push").
3. **INVARIANTS**: "CI (lint + suite on 3.10/3.11) must be green before merge;
   it needs no secrets — the suite is fully mocked."
4. No app code changes → **no version bump** (docs/CI only, mirrors M26.11's
   docs-only precedent). CHANGELOG entry under an Unreleased/CI heading.
