# M30.7 — Claude transport tool restriction — SPEC (→ 3.0.6)

**Status: approved (user, 2026-07-17 triage: "Restrict tools"), implemented.**

## Finding (live desktop testing)

The claude transport is not a passive LLM: in `-p` print mode it is a Claude
Code agent with read-only tools. Observed live: asked about an attachment, it
*searched the filesystem* (its M30.3 neutral cwd — the temp tree), burned
much of a 40–68s turn doing so, and confidently misdiagnosed the upload
system. For Athena, providers are answer engines — tool-calling is an
explicit future feature with its own safety framing (CLAUDE.md Later). A
chat turn should not run tools as a side effect.

## Probed against the real CLI (in-container, before implementing)

- `--disallowedTools "*"` does NOT deny (wildcard isn't a tool name; model
  still had tools).
- Comma-separated explicit names DO deny: with the list below the model
  answered exactly "CANNOT" when asked to use a file tool.
- **Unknown names WARN, never fail** ("Permission deny rule "LS" matches no
  known tool — check for typos", exit 0) — a stale denylist can never break
  answers. This property is what makes a version-brittle list safe.

## Change

`providers/claude.py`:

- Refactor the M28.2 probe: one cached `_cli_help()` (same subprocess
  hardening + neutral cwd) feeds BOTH `_supports_json_output()` and the new
  `_supports_tool_restriction()` ("--disallowedTools" present in help).
- `complete()` appends, when supported:
  `--disallowedTools "Task,Bash,Glob,Grep,Read,Edit,Write,NotebookEdit,WebFetch,WebSearch,TodoWrite"`
  (module constant). Old CLIs without the flag: omitted — agentic behavior
  remains (feature-detected degrade, the M28.2 pattern).

Effects: faster, cheaper, predictable pure-LLM turns; no filesystem
wandering; no more confident misdiagnoses built on temp-dir archaeology.
User-global config (persona etc.) still applies — this restricts TOOLS, not
identity. Gemini has no equivalent flag surface probed here — out of scope
(revisit only if its agentic behavior is ever observed).

## Tests

- Help advertising the flag → completion args carry `--disallowedTools` +
  the exact list; help without it → args unchanged (degrade).
- The help probe runs ONCE for both feature checks (call-count pinned).
- Existing envelope/usage tests unaffected (args assertions checked).
