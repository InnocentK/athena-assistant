# M28.6 — `athena doctor` (preflight diagnostics) — SPEC

**Status: approved (overnight batch). → 2.8.6.**
The executable form of the M26.27 platform matrix: one command that says
whether this host can actually run Athena, and what's missing.

## Design

- **`cli/doctor.py`** — small pure check functions, each returning
  `(name, status, detail)` with status `ok | warn | fail`, so the logic is
  unit-testable without capturing stdout. `run_doctor()` prints an aligned
  report to **stdout** (the report IS the answer — same rule as `athena`'s
  response) and returns the exit code: **1 if any check fails, else 0**
  (warn does not fail the run).
- **Checks are config/filesystem-only — deliberately NO network** (the same
  "availability is config-based, no network probe" rule as the router):
  1. App version (`core/version.py`) + Python version (>=3.10 ok).
  2. `.env` file present; which known provider key NAMES are set
     (`OPENAI_API_KEY`, `XAI_API_KEY`) — **never values**.
  3. Vendor CLIs on PATH (`claude`/`gemini`/`grok`/`hermes`): each found/
     missing (missing = warn — API transports may still cover routing).
  4. Active profile: resolved name (+ source: override/file/env/default),
     `profile.yaml` exists and parses, `memory/` dir present.
  5. Writability of `logs/`, `audit/`, `data/` (fail if missing/unwritable).
  6. Disk free at APP_ROOT (warn < 1 GB).
  7. DAV integrations: enabled flag + URL configured per config file — *not
     probed* (that's runtime's job; doctor must run offline).
- **Entry point:** `--doctor` flag, plus `athena doctor` sugar via the
  existing `_normalize_argv` alias mechanism (like `ask`). Runs before any
  profile/router initialisation and exits with the doctor code.
- **Secret hygiene is the contract:** the output contains key *names* and
  set/not-set only. The test plants a real-looking secret value in `.env`
  and asserts it never appears in the report.

## Tests (`tests/test_doctor.py`, tmp_project-based)
- Healthy tmp project → exit 0, expected rows present (version, python,
  profile resolved, dirs writable).
- Missing profile.yaml → fail row + exit 1.
- Planted `.env` secret value NEVER in output; key name shown as set.
- CLI adapters: `shutil.which` mocked both ways → found/missing rows.
- `athena doctor` argv sugar routes to the doctor (exit 0, no prompt error).

## Self-review
- No network keeps it deterministic, offline-safe, and test-friendly; the
  trade-off (a set key could still be invalid) is documented in the report
  footer ("doctor checks presence, not validity").
- Out of scope: fixing anything (report-only), DAV probes, `task doctor`
  (flag-bearing CLI features skip the Taskfile per repo convention).
