# M26.23 — git init + first commit — SPEC

**Status: specced, awaiting go-ahead. REQUIRES user input at implementation
(identity + remote choice). Do NOT run `git init`/commit without explicit
approval — commit history and authorship are the user's to own.**

## Why

The project is not under version control (verified: `git rev-parse` fails in
both the container copy and on the Mac; no remote). This is the single
foundational gap — without git:
- the CI workflow (M26.20) can't run and pre-commit hooks (M26.26) can't exist;
- there's no history, no `diff`, no `revert` — a weak agent can't recover from a
  bad change or start from a known-good baseline (the whole premise the
  SessionStart hook gestures at);
- "package = zip excluding …" (CLAUDE.md loop step 6) is standing in for what
  should be `git archive`.

Everything built in M26.19–M26.22 assumes git underneath it.

## Decisions to confirm with the user (do not self-answer)

1. **Identity** — `user.name` / `user.email` for the commits (or use an
   already-configured global git identity if present on the Mac).
2. **Remote** — GitHub (turn-key for the M26.20 workflow), GitLab, or
   local-only for now (a remote can be added later; CI stays inert until then).
3. **First-commit granularity** — one commit at the current tree (2.6.21), or a
   short reconstructed history. **Recommend a single clean commit** — the
   per-milestone history lives in `CHANGELOG.md` already; faking granular
   commit dates adds nothing and risks wrong timestamps.

## Scope

1. `git init` in `athena-assistant/` (the packaged root, so the repo travels
   with the code — consistent with CLAUDE.md living inside the project).
2. **Verify `.gitignore` covers everything that must never be committed** before
   the first `git add`. Current `.gitignore` (81 lines) already lists `.venv/`,
   `__pycache__/`, `.env`, `node_modules/` (M26.22), logs, data/exports, etc.
   Audit it against the tree at implementation; in particular confirm:
   `.env` (secrets), `data/carddav_staged/`, `data/restore_staging/`,
   `data/exports/`, `audit/*.log` (keep `audit/` **source**), `.coverage`,
   `htmlcov/`, `*.egg-info/`, `.pytest_cache/`.
3. `git add -A` → inspect `git status` (make sure no `.env`, no `node_modules/`,
   no runtime data staged) → first commit at 2.6.21.
4. If a remote was chosen: create it (`gh repo create …` for GitHub) and
   `git push -u origin main`; confirm the M26.20 workflow runs green.
5. **Docs:** CLAUDE.md loop step 6 ("Package — zip …") updated to note the repo
   is now git-tracked (commits are the record; the zip-exclude list stays for
   the packaging/handoff case). `docs/CI.md` "Activating it" section marked done
   if a remote was set up. Add a short "Version control" note to
   `docs/README.md`.
6. **No app code change → no version bump** (stays 2.6.21). CHANGELOG entry.
