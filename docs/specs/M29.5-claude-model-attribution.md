# M29.5 — Claude model attribution — SPEC

**Status: approved. → 2.9.5.** Refinement of M28.2, driven by validating the
parser against the **real** Claude CLI (2.1.206, run live): the envelope has
**no top-level `model` key** — the model name lives under `modelUsage`
(`{"claude-sonnet-5": {...}}`). Today Claude's diagnostics records therefore
show `model: null`; every other provider attributes its model.

## Scope
1. `providers/claude.py::_parse_json_envelope`: keep the existing top-level
   `model` read (some CLI versions may add it), and **fall back to the first
   key of `modelUsage`** when absent. Defensive: `modelUsage` must be a
   non-empty dict with a string first key; anything else → `None` (never
   guess, never raise — the M28.2 degradation contract).
2. **Pin the real envelope in tests**: add a structurally-faithful fixture of
   the captured 2.1.206 envelope (trimmed values, same shape — extra fields
   like `total_cost_usd`, `cache_creation_input_tokens`, `session_id`,
   `iterations` present so the parser proves it tolerates them) and assert
   content, usage mapping, and `model == "claude-sonnet-5"`. Edge tests:
   empty/non-dict `modelUsage` → `None`; top-level `model` wins when present.

## Version: **2.9.5** (user-visible: Claude turns now carry model attribution
in diagnostics/status/history meta). CHANGELOG + TESTING; INVARIANTS bullet
for M28.2 extended one line (attribution is best-effort, same degradation).
