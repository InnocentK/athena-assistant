# M26.26 — pre-commit hooks — SPEC

**Status: specced, awaiting go-ahead. DEPENDS ON M26.23 (git must exist first).
Do NOT implement without explicit approval.**

## Why

CI (M26.20) catches issues after a push; pre-commit catches them *before the
commit is even made* — the tightest feedback loop, and exactly the guardrail a
weaker future agent benefits from (it can't forget to run the gate; the commit
is blocked until it's clean). Complements, doesn't replace, CI.

## Prerequisite
- **M26.23 (git) is done.** Pre-commit hooks are meaningless without a repo.
  If M26.23 hasn't run, this milestone can't start.

## Scope

1. **Dev dep:** `pre-commit==<pinned>` in `requirements.txt`.
2. **`.pre-commit-config.yaml`** at the repo root with FAST, deterministic hooks
   only (a slow hook trains people to `--no-verify`):
   - **ruff** (`ruff check` + optionally `ruff format --check` if we haven't
     adopted format yet — probably just `check`), via the official
     `astral-sh/ruff-pre-commit` mirror, pinned to the same `ruff==0.15.11`.
   - **mypy** via `pre-commit-mirrors-mypy` (or a local hook calling `mypy .`),
     pinned to `mypy==2.3.0`. Note: mypy-in-pre-commit needs the project's deps
     available — use a `local` hook running the venv's mypy over the repo config
     rather than pre-commit's isolated env, so it matches `task typecheck`.
   - a few stock `pre-commit-hooks`: `end-of-file-fixer`,
     `trailing-whitespace`, `check-yaml`, `check-added-large-files`,
     `check-merge-conflict`, `detect-private-key` (a cheap secret guard).
   - **Do NOT** run the full pytest/vitest suites in pre-commit (too slow for
     every commit) — those stay in `task ci` / CI. Pre-commit is lint+types+
     hygiene only.
3. **Wire it up:** `pre-commit install` (writes `.git/hooks/pre-commit`);
   document that each contributor runs it once. Add `task hooks:install`
   (`pre-commit install`) and `task hooks:run` (`pre-commit run --all-files`).
4. **Make the repo already-clean:** run `pre-commit run --all-files` and fix
   whatever the stock hooks flag (trailing whitespace, missing final newlines,
   large files, YAML) so the hooks are green from day one. These are
   behaviour-neutral text fixes; run the full gate afterward to be safe.
5. **Consistency guard:** the ruff/mypy versions in `.pre-commit-config.yaml`
   MUST match the pins in `requirements.txt` — a mismatch means pre-commit and
   CI disagree. Add an INVARIANTS note to keep them in lockstep (bump both
   together).
6. **CI (optional):** a `pre-commit run --all-files` step in CI as a backstop
   for contributors who skipped `pre-commit install` — decide at implementation
   (it partly duplicates the ruff/mypy CI steps; may not be worth the minute).
7. **Version:** tooling + possibly some whitespace/EOF text fixes → **no bump
   unless the stock hooks touch real `.py` logic** (they shouldn't — they're
   formatting hygiene). Likely no bump. CHANGELOG + INVARIANTS.

## Self-review notes
- Keep it FAST. If mypy-in-pre-commit is too slow on large commits, drop it to
  pre-push (`pre-commit install --hook-type pre-push`) and keep only ruff+hygiene
  at pre-commit. Decide from real timing.
- `detect-private-key` + `check-added-large-files` are cheap insurance against
  the two worst commit mistakes (a key, a 100MB blob) — keep them.
- Hooks must be **bypassable in emergencies** (`git commit --no-verify`) — that's
  fine; they're a default, not a lock.

## Out of scope
- Commit-message linting (conventional-commits), signed commits, CI-side
  commit-lint.
