# M31.1 — Mobile voice enablement — SPEC (→ 3.1.1)

**Status: approved (user, 2026-07-19: "Yes, implement now") — the user's
first probe target for M31.0 conversation mode is Athena UI (mobile).**

## Problem

Conversation mode (M31.0) cannot be used on a phone at all, for two stacked
reasons found when the user asked to test it there:

1. **The mic button doesn't exist on narrow screens.** The M28.4 mobile pass
   added `#ptt-btn { display: none; }` under 600px to save footer space — a
   fine call when the mic was a dictation nicety, wrong now that the mic
   click is the ONLY control that arms the hands-free loop (M31.0's
   gesture-armed invariant).
2. **The mic requires a secure context.** Bare `http://<tailscale-ip>:8000`
   grants no microphone access on any phone browser — the same constraint
   that hid the PWA install (PLATFORMS.md). Not a code problem: the
   documented `tailscale serve --bg 8000` step (REMOTE-ACCESS.md) gives the
   HTTPS tailnet URL. Speech OUTPUT already works over plain HTTP.

## Change (CSS + docs only; no JS, no backend)

- Remove the `display: none` and replace it with compensating narrow-screen
  sizing: mic slimmed to 34px, attach button padding tightened. Footer at
  375px: attach (~38) + mic (34) + Send (~55) + 3×6 gaps ≈ 145px, leaving
  ~210px of textarea — comfortable.
- **Pin it**: `test_ui_correctness.py` asserts the narrow-screen media block
  restyles `#ptt-btn` but never hides it (`display: none` banned in every
  `#ptt-btn` block from the media query on).
- Docs: PLATFORMS voice section — mobile becomes "works over HTTPS,
  Chromium/Safari", with two phone realities stated honestly: switching
  apps / locking the screen disarms the loop BY DESIGN (visibilitychange —
  never a hidden hot mic in a background tab), and iOS may need one
  Test-voice click to unlock audio the first time. CHANGELOG 3.1.1;
  CLAUDE.md epic entry (M31.1 shipped; **Athena Live renumbered M31.2+**);
  specs/README row.

## Not in scope

- Running `tailscale serve` — operator step on the user's Mac, their call.
- PWA/mobile-specific voice UI beyond the button (wake lock, larger touch
  target experiments) — candidates only if the probe earns them.

## Self-review / risks

- Risk: footer crowding on very narrow (<360px) devices. Accepted: worst
  case the textarea shrinks; every control keeps a ≥34px touch width.
- Risk: Android Chrome continuous-mode quirks (auto-end on silence).
  Already true for M30.6 dictation; the loop's re-arm makes it self-healing
  (utterance ends → mic re-opens). Verified by the user's live probe, not
  jsdom.
- The M31.0 CSS (`.conversation-live` ring) needs no mobile variant — it is
  border/box-shadow on the same button.
