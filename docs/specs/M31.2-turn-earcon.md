# M31.2 — Audible turn indicator (earcon) — SPEC (→ 3.1.2)

**Status: approved (user, 2026-07-19: "M31.2 earcon, keep probing") — the
first lived-experience refinement produced by the M31.0 probe.**

## Problem / decision record

Probe finding #1 (user, day one, on the phone): conversation mode works
well, but hands-free means eyes-free — there's no way to *hear* that Athena
finished and the mic re-opened. The user asked whether the cue would be
wasted work once Athena Live exists. Answer argued and accepted: **no** —
a turn cue is transport-independent turn-taking UX (ChatGPT voice keeps its
chimes despite a far fancier pipeline), Athena Live's cascade is still
turn-based until its final barge-in stage, and the cue sits at the same
"mic re-opens" seam in both worlds. The Live epic itself stays gated on
lived experience per the M31.0 rule; it renumbers to **M31.3+**.

## Change (browser-only, ~50 lines)

A short rising two-tone blip (Web Audio: sine 880 Hz → ~1175 Hz, ~160 ms
total, low gain, no audio files, no dependencies) plays **only when the
hands-free loop AUTO-reopens the mic** — in `_convoResume()`, after the
guards pass, before `startListening()`. A manual mic click never blips (the
user clicked; they know).

Autoplay policy: the `AudioContext` is created/resumed by `_earconUnlock()`
inside the **same mic-click gesture that arms the loop** — the earcon rides
the existing gesture-armed invariant (M31.0). No context / suspended
context / any Web Audio failure → silent no-op, never a broken loop.

No new pref for the probe: the cue is intrinsic feedback for a mode that is
itself opt-in. If lived experience wants a toggle, it's a
`_voiceToggleRow` away.

## Tests

- jsdom (fake AudioContext): auto-reopen plays ≥2 oscillators; a manual
  mic click plays none (unlock only); conversation OFF creates no context
  at all. The existing M31.0 loop tests run WITHOUT any AudioContext fake —
  their continued passing IS the no-Web-Audio degradation proof.
- Pins: `_playTurnEarcon(` count = 2 (definition + the one `_convoResume`
  call site); `_earconUnlock(` count = 2 (definition + the mic-click arm
  branch — the gesture invariant).

## Self-review / risks

- Mic hears the blip: it starts just before `startListening()` and is
  ~160 ms of pure tone at low gain — SpeechRecognition ignores non-speech
  audio; this is the standard pattern in shipping voice products.
- A3 immediate re-arms (failed turns) also blip — deliberate: the cue means
  "mic is hot", which is exactly true there.
