# M28.4 — mobile-responsive UI pass — SPEC

**Status: approved (overnight batch). → 2.8.4.**
(Renumbered from the roadmap's "M28.6": shipped out of order because it's the
smallest of the batch; milestone==version must stay monotonic, so the mobile
pass takes the next free number. Profile switcher → M28.5, doctor → M28.6.)

## Why
M26.28 (PWA) + M28.3 (remote-access doc) made "phone over Tailscale" a real
path, but the dark UI was built for desktop. An `@media (max-width: 600px)`
block already exists (spacing/badge trims); what's missing is the
phone-specific correctness layer. CSS-only + one viewport-meta attribute; no
logic changes.

## Scope (all measured against the current stylesheet)
1. **Panels full-width on phones.** `.memory-panel`/`.settings-panel`/
   `.history-panel` are fixed `width: 340px` — on a 375px screen they leave a
   sliver of dead chat visible. → `width: 100%` inside the small-screen query.
2. **Kill the iOS focus-zoom.** `#message-input` is `0.875rem` (<16px), which
   makes iOS Safari zoom the whole page on focus. → `font-size: 16px` in the
   query (desktop unchanged).
3. **Dynamic-viewport height.** `#app { height: 100vh }` overflows under
   mobile browser chrome. → add `height: 100dvh` after it (progressive
   enhancement; old browsers keep 100vh).
4. **Safe-area insets (notched phones, PWA standalone).** `viewport-fit=cover`
   on the template's viewport meta + `env(safe-area-inset-*)` padding on
   `#app` so the header/input aren't under the notch/home bar. Insets are 0 on
   non-notched devices — no visual change elsewhere.
5. **Tap targets.** Header buttons get `min-height: 36px` + a bit of padding in
   the query.
