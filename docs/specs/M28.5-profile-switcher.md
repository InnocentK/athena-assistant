# M28.5 — runtime profile switcher — SPEC

**Status: approved (overnight batch). → 2.8.5.** Completes M28: an imported
portable profile becomes usable without editing `ACTIVE_PROFILE` + restarting.

## Design

**Resolution order** (`core/config.py::_resolve_active_profile`, M28.5):
1. `ATHENA_PROFILE_OVERRIDE` env — process-scoped explicit override; the CLI's
   `--profile` flag now sets THIS (not `ACTIVE_PROFILE`), so the flag beats
   the switch file too.
2. `config/active_profile.yaml` (`active_profile:` key) — the runtime-switch
   persistence file, written ONLY by `POST /profiles/activate`. Deliberately
   beats `ACTIVE_PROFILE`: `.env` sets that on default installs, and a UI
   switch must survive a restart there. Defensive read — a broken file falls
   through to env (must never brick boot). Delete it (or switch back) to
   return control to the environment.
3. `ACTIVE_PROFILE` env (dotenv). 4. `"athena"`.

**Endpoints** (core router, beside `GET/PATCH /profile`):
- `GET /profiles` — dirs under `profiles/` with a parseable `profile.yaml`:
  `{name, display_name, active}`.
- `POST /profiles/activate {name}` — name must match `^[A-Za-z0-9_-]+$`
  (400; blocks traversal), profile must exist (404) and parse to a non-empty
  mapping (400). Then, off the loop: write the switch file (`save_yaml`),
  `get_settings.cache_clear()`, `_profile_data.clear()+update(new)`, re-point
  `main._memory` / `main._saved` at the new `active_profile_dir()`. Router/DAV
  are config-scoped, not profile-scoped — untouched. Ops-audited
  (`profile_activate`). **Never touches `.env`.**

**Semantics:** in-flight requests finish against the OLD managers (handlers
bind `main.X` at call time — the M26.18 router-split pattern); new requests see
the new profile. Single-user; no cross-request locking added. CLI picks up the
switch file on its next run automatically.

**UI:** settings panel → Profile tab gains an "Active profile" select +
Activate button (shown only when >1 profile exists), POSTs and does a full
`location.reload()` on success (name/memory/saved all change). Uses the
existing `_settingsSelect`/`_settingsControlRow` helpers + `_panelLoadToken`
guard (M26.10 invariants respected: canonical value always a selectable option
by construction).

## Tests
`tests/test_profile_switch.py` (6): list marks active; activate switches state
(+file, +settings, +`/profile`+`/health` reflect it) ; bad names (traversal)
400 / missing 404 / invalid yaml 400; resolution order override>file>env;
broken switch file falls through to env. Plus an **autouse conftest guard**
clearing `ATHENA_PROFILE_OVERRIDE` between tests — the CLI is one-shot in
production but in-process in tests, so the flag's env write would leak into
later tests' Settings resolution (this bit: 32 failures before the guard).

## Self-review

  needs the same conftest treatment.
- UI is backend-tested only (endpoints); the dropdown itself follows the
  established settings-panel patterns — jsdom coverage can be added when the
  settings tab gets its own harness boot (the current loadChat skeleton
  doesn't render the settings body).
- Out of scope: per-profile provider config (config/ stays global), profile
  creation/deletion endpoints (import/backup cover creation), auth (n/a).
