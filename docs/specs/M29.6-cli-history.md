# M29.6 — CLI history surfaces — SPEC

**Status: approved. → 2.9.6.** Closes the M29 asymmetry: the REPL writes
conversations it cannot read back. After this, both surfaces are full
citizens of persistent history.

## Commands (`athena history …`, routed before the main parser like a true
subcommand; `ask`/`doctor` aliases unaffected)

- `athena history` — list, newest first: id, started, turns, preview.
  **stdout** (the list IS this command's answer — same rule as
  `--list-providers`).
- `athena history <id> [<id> …]` — human-readable transcript(s) to stdout,
  in the order given, `---` rule between conversations. (`You:` /
  `Assistant (provider/model):` lines; failed turns marked.)
- `athena history export <id> [<id> …]` — Markdown to stdout, same
  ordering/separator. Redirect for one merged doc; shell-loop for separate
  files (documented — the deliberate scope cut recorded in Later/unscheduled).
- `athena history export --all` — every conversation, newest first.
- Errors (bad/unknown id) → stderr + exit 1; empty store → friendly notice
  on stderr, exit 0 for `list`, exit 1 for id-addressed commands.

## REPL additions
- `/list` — recent conversations to **stderr** (inside the REPL it's status,
  not an answer).
- `/resume <id>` — load the stored turns as in-session context (**success-only
  replay**, the M26.10 rule) and continue appending to that same conversation.
  Bad/unknown id → stderr message, session continues.

## Shared renderer (the M29.0 philosophy)
- `history/manager.py` gains `render_markdown(conversation_id) -> str` —
  the Markdown builder MOVES out of `app/routers/history.py`; the HTTP export
  endpoint delegates to it. One renderer, two surfaces; the store's id guard
  remains the single validation point.

## Tests (`tests/test_history_cli.py` + REPL additions)
List/show/export single + multi (order + `---` separator) + `--all` (newest
first) against a seeded store; unknown id → exit 1; transcript marks failed
turns; HTTP export regression stays green (renderer move is behavior-
preserving — existing `test_history.py` export tests are the net).
REPL: `/resume` gives the next `route()` call the prior turns and appends to
the same file; failed stored turns are not replayed; `/list` prints to stderr.

## Self-review
- `history` as a pre-parser token (like `doctor`) keeps the main argparse
  untouched — no flag explosion.
- Profile resolution: the subcommand uses the standard resolution (switch
  file > env > default). `--profile` with `history` is out of scope (the
  switch file is the persistent mechanism); document.
- Out of scope: zip bundles / export-all endpoint / date ranges (recorded in
  Later/unscheduled), deletion via CLI (files are plain JSONL on disk).
