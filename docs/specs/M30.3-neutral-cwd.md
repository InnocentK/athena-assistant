# M30.3 — Neutral cwd for CLI provider subprocesses — SPEC (→ 3.0.2)

**Status: approved (user, 2026-07-16), implemented.**

## The finding (from a live incident)

`athena --provider claude "hello"` run from inside the Athena repo answered
as "Athena, ready to help with the Athena Assistant codebase" — after 54
seconds. Cause: CLI provider adapters run vendor CLIs via `subprocess.run`
with an **inherited working directory**. Claude Code discovers project
context by walking up from cwd, so it loaded the repo's `CLAUDE.md`, executed
the SessionStart hook (ruff + mypy + the full 593-test suite — most of the
54s), pulled ~15k tokens of cached project context into the call, and
answered in the repo-agent persona instead of as Athena.

This generalizes: `athena` run from inside ANY project directory leaks that
project's agent configuration (instructions, hooks, their cost and their
side effects) into what is supposed to be an Athena chat with Athena's own
profile as the only context. Gemini (GEMINI.md) and other vendor CLIs have
the same cwd-discovery convention.

## Change

`providers/base.py` gains `neutral_cwd()` → `tempfile.gettempdir()`, and all
five CLI subprocess call sites pass `cwd=neutral_cwd()`:

- `claude.py` — the `--help` JSON-support probe AND the completion call
- `gemini.py`, `grok.py` (cli transport), `hermes.py` — the completion calls

The system temp directory is outside any repository, so upward config
discovery finds nothing project-level. Uniform across adapters regardless of
whether each vendor reads cwd config *today* (future-proofing is the point).

**Blessed limitation:** user-GLOBAL vendor config (e.g. `~/.claude/`) still
applies — that is the operator's own CLI identity/login, which Athena must
not strip (it's how the CLI authenticates). The boundary drawn here is
project-level context, not user-level.

## Tests

`test_provider_robustness.py` additions: for each of the five call sites
(mocked `subprocess.run`), assert `cwd == tempfile.gettempdir()` — same
style as the existing stdin/encoding hardening assertions.

## Docs / version

Version → **3.0.2** (behavior change). INVARIANTS: the CLI-adapter hardening
rule gains "run from `neutral_cwd()`". TROUBLESHOOTING: new entry for the
symptom ("answers sound like a coding agent for the directory I'm in / are
very slow there") noting it's fixed from 3.0.2 and the workaround on older
versions (run `athena` outside project directories). CHANGELOG, specs README,
CLAUDE.md roadmap.

## Self-review / risks

- Vendor CLIs that write scratch files relative to cwd now write into the
  temp dir — acceptable by definition of a temp dir.
- No test previously asserted an inherited cwd; nothing else in the adapters
  reads relative paths at completion time (prompts are passed as arguments).
- The streaming surfaces are unaffected: CLI transports don't stream (M30);
  route()/route_stream() call the same `complete()`.
